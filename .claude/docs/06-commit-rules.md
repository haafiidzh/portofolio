# 06 — Commit Rules

### Commit Rules

- Use prefixes such as `feat: ...`, `fix: ...`, `chore: ...`, `refactor: ...`, `docs: ...`, etc., for every commit message.
- Commit messages must be in a single-line format; if the message is long, use a semicolon (;) or comma (,) to separate parts.
- Do not commit all changes at once; instead, dedicate one commit to a single context of change, and proceed accordingly.
- AI-generated commit messages are prohibited (e.g., "Generated with Claude Code" or "Co-authored-by: Claude noreply@anthropic.com").

### Allowed Commit Message Example

- `feat: add responsive navigation menu`
- `fix: correct mobile layout on about page`
- `refactor: extract shared header and footer; update all pages to use reusable components`
- `style: improve landing page layout; standardize typography, spacing, and button styles`
- `feat: create new FAQ page; add categorized questions and expandable answers`
- `feat: implement contact form, add field validation and success messages`
- `fix: correct mobile layout on about page; prevent content overflow on small screens`
